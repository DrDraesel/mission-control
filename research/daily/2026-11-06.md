### `0xS4N4TG/kinetograph` — 475★ (was 115★ on 10-27), npm 0.3.0, **PolyForm Small Business 1.0.0** — the best agent render path found this quarter

A browser-free programmatic video engine: you (or an agent) write a video in **TypeScript with Remotion's API** (or plain **HTML + GSAP**), Node runs the code, and a **Rust GPU compositor loaded as an N-API addon** draws every frame (wgpu → **Skia GPU/Vulkan** on Windows: vectors, text, Canvas 2D, WGSL effects, GLSL via naga, scene3d glTF/PBR, ThorVG Lottie, 2.5D camera, motion blur, layer cache). It **maps `remotion` / `@remotion/*` imports to its own implementation, so existing Remotion projects render as-is**, and since 0.2.0 it also **renders HyperFrames projects**. Bundled ffmpeg supplies x264/x265/VP9/ProRes.

Measured on this box (Windows 11, RTX 5070 Ti):

| Step | Command | Result |
|---|---|---|
| help | `npx -y kinetograph@latest --help` | exit 0 — 20 commands |
| init | `kinetograph init demo --html` | 7 files; `html/index.html` + `public/{audio,fonts,images,video}` + `out/` |
| render | `kinetograph render html/index.html` | **main.mp4 1280×720, 60 f @30 fps, h264/yuv420p, 12.93 s total** (4.69 ms/frame in the encoder; 29 frames deduped as unchanged), renderer line: `Skia GPU (Vulkan)` |
| deps | (automatic) | fetched GSAP from jsdelivr into `~/.cache/kinetograph/cdn` + wrote `kinetograph.lock.json` — `--offline` then guarantees reproducibility |
| lint | `kinetograph lint html/index.html` | `no issues (frames 0, 8, 17, 25, 34, 42, 51, 59)` — samples frames, not just the DOM |
| prores | `render --codec prores --prores-profile 4444 --pixel-format yuv444p10le --range 0..5` | prores_ks wrote **yuv444p12le** — 4444 profile works but **NO alpha plane** (no `--transparent`/alpha flag exists; grep of `render --help` = 0 hits) |
| doctor | `kinetograph doctor` | node v24.18.0 win32-x64, addon loaded 0.3.0, Skia GPU (Vulkan), "0.3.0 is the latest" |

Command surface (all take `--json`): `init`, `add` (registry of components/templates/tastes), `compositions`, `still`, `render`, `strip` (contact sheet), `onion` (motion path), `inspect` (scene graph at a frame), `lint`, `check` (`tsc --noEmit` for typos that render silently), `bench` (ms per stage), `audio analyze` (**LUFS / true peak / clipping / silences** = the delivery gate), `track` (**Blender's tracker** → `*.track.json`), `snapshot` (frame regression vs approved PNGs), `effects`, `plugins` (each plugin ships a `SKILL.md`), `doctor`, `fetch-deps`, `studio` (browser timeline), `mcp` (stdio MCP server, one tool per command).

Judgement: **this is the render engine the pipeline was missing.** It removes the Chromium dependency (and its EPERM/unpack class of Windows bug), gives a real `lint`/`snapshot`/`audio analyze` QC chain, and its Remotion API compatibility sidesteps Remotion's ≤3-employee licence. Gaps: **no alpha export** (OpenEdit stays the transparent-overlay path), PolyForm Small Business (fine for own/client work; redistribution needs the notice), and `--preferred-effect-backend` is still young.

### `OpenShot` — 6,750★, v4.1.1 (Win x86 exe 232.5 MB) — **shipped a headless agent CLI and nobody noticed**

Verified from the repo tree (`develop`, 8,129 files) + in-tree docs `doc/agent_cli.rst` (48,520 B): OpenShot 4.1 (Oct 25) added a **command-line interface with headless sessions**:

- Windows entry point is **`openshot-qt-cmd.exe --cli <command>`** (the GUI exe prints nothing to a terminal — documented explicitly).
- `session start` (headless, no window) → `file import` → `clip add --position/--start/--end` → `clip motion --preset slide-in-left` → effects/text/transitions/keyframes → `export start out.mp4 --wait`, all returning **JSON** (`--json '{...}'` payloads, `@batch.json` batch files).
- **Batch-export several saved `.osp` projects in one session**, `export validate` (same checks as the dialog), `export --mode image_sequence|audio`, `--start-frame/--end-frame` range renders, and bulk edits via selector: `edit bulk --select '{"text":true}' --json '[{"method":"text.set","params":{...}}]'`.
- Live hand-off: `session show` brings the agent's project into the open GUI with edits, undo history and export jobs intact.

This converts a "GUI editor already in the ledger" into a **first-class Premiere replacement with a headless CLI**. Still experimental, and not yet installed here — **queued as tomorrow's on-machine test** (silent install + `openshot-qt-cmd.exe --cli help` + a 3-clip export).
