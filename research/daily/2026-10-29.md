## 2. Top finds today

### ⭐ 1. `Agents365-ai/drawio-skill` — 10,436★ MIT — text/code/IaC → editable `.drawio`, with a CLI and a CI gate
"From Text to Professional Diagrams." Works with **Claude Code, Cursor, Copilot, Codex, OpenClaw, Hermes** and any Agent Skills host.
- **Generation**: prompt → planned layout → `.drawio` XML → export → **self-checks its own PNG and auto-fixes overlaps, clipped labels and stacked edges** (2 rounds, 5 rounds of human feedback).
- **Inputs that matter to us**: 11 diagram presets (ERD, UML, Sequence, C4, Architecture, ML, Flowchart, BPMN, Network, Swimlane…), **Mermaid → native `.drawio`** (needs draw.io ≥ 30), **screenshot/whiteboard photo → editable diagram** (vision extract → `raster2drawio.py`), **code import graphs** for Python/JS-TS/Go/Rust + Python class hierarchies, **Terraform / K8s / docker-compose** with official cloud icons, SQL DDL → ERD, OpenAPI → API diagram, Protobuf/GraphQL/AsyncAPI, GitHub Actions → DAG.
- **The part that is actually new**: a **Diagram IR** (meaning/provenance/geometry separated) with `diagramctl sync` that updates changed nodes while **preserving hand-tuned layout**, multi-view projection (executive/system/deployment/data-flow/security from one model), `diagramctl query/test/whatif/story` and **Diagram-as-Test rules in CI** (GitHub Action renders visual diffs).
- **Core workflows are stdlib-only and offline**; optional MCP server; layout needs Graphviz (optional). Windows requirement: the **draw.io desktop CLI** (`jgraph/drawio-desktop`, GPL-3.0, already ledgered 10-28) ≥ 30 for Mermaid→drawio and `--layout`.
Why it matters: this is the missing *deterministic* layer between "the agent wrote an architecture" and "a client-facing diagram exists" — and the CI rule engine is the same shape as impeccable's detector gate. Pairs with archify (HTML diagrams) and anatomy (isometric figures).

### 3. `NomaDamas/CozyClay` — 1,156★ AGPL-3.0 — 3D previs *before* you pay an AI video model
"Make the scene first. Then make it a video." A browser 3D greybox studio: block the set, block the cast, compile the motion, cut the camera, then **export first frame + greybox reference clip + a prompt that describes the real framing** to the video model.
- Pipeline: Stage (set + cast) → Motion (compiled + QA) → Camera (shots + cuts) → Export (frame · clip · prompt) → AI video model.
- **npm 3.2.1, Node 22.19+, `npx cozyclay` for the studio and `npx cozyclay mcp` for agent control** (smoke-tested today, exit 0); `cclay live status` reads/drives a running studio; AGPL-3.0 (fine locally, flag for client redistribution).
- Why it matters for 16 GB: it removes retries — the expensive part of local/H3/LTX generation is re-rolling because the shot was wrong, not the sample itself. This is the cheap place to fix composition and timing.
Caveat: AGPL + it is a *previsualiser*, not a renderer; it needs a video model behind it (local or paid).

### 4. `geeklee/srt-whiteboard-animation` — 5,144★ MIT — SRT subtitles → hand-drawn whiteboard MP4
A Python skill (own venv bootstrap, `scripts/prepare_env.py --check` prints `ENV_PY=`): parses SRT → splits into 25–35 s scenes → storyboard/image plan → **`annotation.json` with regions, sequence, subtitle binding and protected overlap zones** → **streaming ink→colour stroke renderer** per scene → `merge_scenes.py` to a final MP4. Warm cream paper `#F5EBD7`, dark-grey sketch lines, hand asset included, browser preview台 for retiming regions.
Why it matters: this is the **faceless-explainer** format that Canva/whiteboard SaaS sell, driven by nothing but the subtitle file we already produce — pure Pillow/ffmpeg-class dependency, no model, no browser rendering. Caveat: Chinese-first docs, single push on 2026-07-27 (one-day repo), untested on this box.
