## 1. Verified on this machine — `raea` renders 1080p at **6.2 ms/frame** with no browser

**`shinyobjectz/raea` — 1,851★, FSL-1.1-ALv2, created 2026-10-18, pushed today, Rust + Bevy.** Render Anything Engine: compositions are React + TypeScript, and a Rust/Bevy engine draws them straight on the GPU — **no Chromium, no page screenshots, no Node render loop**.

**On-box evidence (installed and run in this sweep):**
- `raea.io/install.ps1` → **raea 0.1.1-rc1** under `~/.raea` (sha256-verified release zip; the skills-copy step has a harmless `Select-String` miss on `~/.claude/skills/raea-bevy/SKILL.md`).
- `raea render hello.tsx -o hello.mp4` → **90 frames 1920×1080@30 in 4.65 s wall = 6.2 ms/frame, 199.7 fps including encode**, H.264 47.6 KB (`pprof`: submit 0.087 ms, copy 0.61 ms, sink 1.47 ms per frame). Frame at t=0.8 s inspected: white "Hello" on black, correct layout.
- `raea check hello.mp4` → **"nothing to fix"** (frozen / flashing / blotching checks ran and passed).
- `raea render hello.tsx -o alpha_out --alpha` → **RGBA PNG sequence, 1920×1080, pix_fmt=rgba** plus per-frame lighting warnings ("99.6% of pixels crush to black" — it meters the frame, not just renders it). Video alpha is refused with the exact ffmpeg ProRes 4444 command to encode the folder, which is the honest behaviour.

**Why it matters:** this is the first render path measured on this box that beats every incumbent by an order of magnitude. For comparison, measured here on earlier runs: OpenEdit **105 ms/frame** (headless Chrome), kinetograph **~430 ms/frame** (Skia via wgpu), HyperFrames — same Chromium class. raea is ~17× OpenEdit and ~70× kinetograph at the same 1080p output, and it removes the browser from the dependency graph entirely.

**The CLI is far bigger than a renderer:** `cut` (transcript-timed cuts → cuts.ts + words.json), `track` (camera solve → matchmove JSON), `song` (beat/section/energy map → `--srt` aligned), `splat` (footage → Gaussian splat), `gen` (image/video/music/sfx/speech via fal/Replicate/ComfyUI — **`gen comfy import` takes an existing ComfyUI workflow**), `blender run` (headless), `media` (native ffmpeg verbs: probe/still/sheet/loudness/motion/cuts/freezes/proxy/trim/concat), `check` (delivery gate: clipped text, contrast, safe areas, freezes, flashing, cues, loudness, P0–P3), `brand` (brand kit from a URL), `guide` + `context` (craft floors an agent reads), and `hook`/`skills install` for Claude/Codex/Gemini/Kimi.

**Caveats, stated plainly:** canary release, Windows is the **least tested** platform (README's words), FSL-1.1-ALv2 — free for any use **except a product that competes with raea**, each version becomes Apache-2.0 two years after release. 1.0 GB Linux tarball vs 316 MB macOS (the Windows zip is what the installer pulls).

## 8. Integration plan

1. **Adopt raea as the primary code-render path, gated.** Keep HyperFrames/OpenEdit as the fallback for anything that needs real HTML/CSS layout, and move motion-graphic reels to `raea render`. Measure one real 30 s reel this week: if it holds at <10 ms/frame, the Chromium render loop is dead weight.
2. **Wire `raea media` + `raea check` into the shorts gate** — the check already returns P0–P3 findings for clipped text, contrast, safe areas, freezes, flashing and loudness; that is the delivery gate we have been assembling from three separate tools.
3. **Use `raea cut` for transcript cuts** (it writes `cuts.ts` + `words.json`) and feed the same words to `captions.js`/`seconv` for burned captions. One timing source, three renderers.
4. **Static social assets → takumi** (JSX → PNG/PDF, no browser) with astryx components and impeccable as the lint gate.
5. **Try `raea gen comfy import`** after the ComfyUI update — it makes every ComfyUI workflow callable from the same CLI that renders, which is the shortest path from "generated plate" to "finished frame".
6. **ComfyUI update remains the standing #1 action** (19 versions behind, 27th run). It now gates WeVisOne-VL, RevealLayer, the LTX-2.5 templates, Kandinsky 6, MatteDesk's LTX stage, ReAngle and openjutsu.
