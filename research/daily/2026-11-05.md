### The Windows bug worth knowing
`openedit render` tries to install its pinned **Chrome Headless Shell 153.0.8010.12** (114.6 MB, checksum verified) into `%APPDATA%\veed-openedit\browser\`, then dies with **`EPERM, Permission denied: \\?\…\chrome-headless-shell-…tmp-<pid>-<hash>`** — the temp→final rename never happens and no browser is registered. Workaround that works: **`--chrome "C:/Program Files/Google/Chrome/Application/chrome.exe"`** (or set `OPENEDIT_CHROME`). The shim does this already. `install-browser --force` will hit the same wall until they fix it.

## Top finds

### 1. OpenEdit — an agent-driven editing pipeline with a real renderer, real alpha, and a QC gate (the AE/Premiere-shaped hole)
- **`veedstudio/open-edit` — 1,779★ Apache-2.0**, repo created 07-22, **pushed today** (30 commits, mirrored from VEED's internal `veed-llm-editor` via Copybara). It has been in the ledger since **2026-09-25** (`motion-graphics`/`fresh-motion` queries) but had never been installed or measured — a good reminder that "ledgered" ≠ "evaluated".
- **Shape:** no GUI, no timeline. Install the skill (`npx skills add veedstudio/open-edit --skill open-edit`), tell Claude Code / Codex / Gemini CLI "add subtitles that look like this to my video", and the agent writes a **page (HTML/CSS/JS)** which is rendered **frame-exact** to MP4. Every deliverable under `runs/<key>/` keeps the page that made it, so an edit is a one-line change and a re-render.
- **What the CLI actually contains** (all verified present in `--help`): `transcribe` (VEED hosted, or **WhisperX locally** via `install-whisperx`, uv/pipx), `whisper`/`words` (map any ASR JSON), `brief`, `shots` (shot list + storyboard sheets), `faces` (MediaPipe), `captions`, `reframe` (face-following 9:16/1:1 at 1080 px), `render`, `install-browser`, `fonts` (Google Fonts → local woff2), `safe-zone` (platform canvas + text-safe layer), `speech-probe`, `apply-edl` + `retime-transcript`, `mux-audio`/`mix-audio` (ducking, loudnorm), `concat-videos`, `frames`, `behind` (how much of a graphic survives the cut-out), `stills` (Wikimedia Commons, licence recorded per file), `fal` (BYO key), `veed-project`/`veed-pull` (hand to VEED as an editable project), **`review`** (delivery checks), `init`.
- **The renderer is the point.** `render <page.html> --out x.mp4 [--fps] [--duration|--frames] [--width/--height] [--workers] [--segment] [--from/--to] [--transparent] [--footage clip --footage-at t] [--stills] [--sheet]`. The page runs on a **virtual clock** — `performance.now`, `Date.now`, rAF, `setTimeout`, `setInterval` all advance exactly one frame at a time, `Math.random` is seeded, CSS/Web Animations are set per frame, GSAP's global timeline is seeked, and `window.__seek(t)` is awaited if present. `--workers` parallelises contiguous frame runs; `--from/--to` re-renders only changed 2 s segments and rejoins; `--footage` lays a page captured **with alpha** over a clip (captions/graphics over real footage); `data-cutout="<vp9 webm>"` stacks behind/cutout/front layers.
- **Measured on this box:** 640×360 page → MP4 60 f @30 fps **6.3 s**, 105 ms/frame, page work 2 ms/frame + capture 80 ms (the capture is Chrome; the page is not the cost). Transparent ProRes 4444 **175 ms/frame**. It also writes `<render>.text.json` for the review gate.
- **`review` is a real delivery gate, not advice:** dead-tail, dead-air, length, canvas, blank-frames, text (size floor 16 px + measured contrast ≥3:1 sampled over frames), captions, numbers (does the spoken number match the on-screen number), graphics, brief. Today: `canvas FOUND (short side 360 < 1080)`, `blank-frames pass`, `text pass (1 text ≥16px, 3:1 against what is behind)`. Exit tells you what you left in.
- **Licence split:** pipeline + CLI **Apache-2.0**; VEED's own **render engine binaries are closed, PolyForm Shield 1.0.0** — free to use, and **you can sell what you make with them at no cost to VEED** (PolyForm Shield forbids competing with the product it protects, not commercial use of outputs). The headless-Chrome path used here needs only the Apache CLI.
- **Why it matters for this pipeline:** it replaces the flakiest step of every IG/faceless job — "get a designed page onto video with alpha and a check" — with one CLI that has an **alpha output**, **safe zones**, **local WhisperX**, **local fonts**, and a **QC gate**. That is the After Effects + Media Encoder + eyeball loop, minus the apps. MeerCut still owns the NLE/trim/grade side (and cannot export alpha); OpenEdit is the motion-graphics/overlay side.

## Integration plan (ordered)

1. **Adopt OpenEdit as the motion-graphics/overlay renderer.** `openedit` shim is on PATH. Pattern per job: agent writes `page.html` → `openedit render page.html --out overlay.mov --transparent` → composite in MeerCut/`fa-render` (MeerCut cannot *export* alpha, but it can import a ProRes 4444; test the import path before relying on it) or use `--footage clip.mp4` to let OpenEdit do the layering itself.
2. **Gate every render with `openedit review`.** It returns concrete findings (canvas, blank frames, text size/contrast, caption/number mismatch) — wire it after `fa-render` too by passing `--transcript` and `--brief`.
3. **Fix the browser path once:** `install-browser` is broken on this Windows build (EPERM temp rename). Keep `OPENEDIT_CHROME` in the shim; file nothing upstream unless we start depending on the pinned build.
4. **Put `rea-video` in front of IG/Method work**: deconstruct 3 competitor reels per week into shot lists → prompts for our own boards (Apache, offline tools mode, ffmpeg + Python 3.10+).
5. **Speech stack:** `pip install moonshine-voice` (in-process STT) and try `Handy` for dictation; `index-tts` for cloning experiments; keep `edge-tts` for fast VO. All local, no keys.
6. **ComfyUI 0.44 update stays #1** — it is the only thing blocking every local-video wrapper found in the last two weeks (Kinoloom, MagoStudio, ReAngle, LeafReel, MatteDesk's LTX stage, openjutsu).
