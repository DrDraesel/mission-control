## 1. Verified on machine

### `lovisdotio/motion2code` — 361★ MIT, created 2026-10-20 — **reference video → code, with a measured gate**

The missing half of "recreate this clip": it is not a generator, it is a **QA loop** that forces an agent to look at the
source before writing code, then proves the rebuild frame by frame.

Cloned and run with plain project python + ffmpeg 9.0.2 (no Playwright download — `launch()` tries the installed Chrome first):

| script | what it did on `gallery/think-big/source.mp4` | result |
|---|---|---|
| `study_video.py` | 854×480 24 fps 10.125 s → **40 frames** @0.25 s, frames around every hard change, 6×4 contact sheet, flat palette | **2.64 s wall**; cuts at `[1.0, 3.083, 5.167, 9.167]`; palette `#FBFBF7 60% / #007BE1 31% / #F3DE00 7%`; source loop seam **0.11 → "already loops"** |
| `check_anim.py` (static) | 6/6 gallery pages | all `[ok]` — allowlisted CDNs only (GSAP 3 cdnjs, flubber jsdelivr), no `<img>/<video>/canvas.drawImage`, `window.anim.{duration,seek,play,pause}` contract, `?external=1`/`?t=` handled |
| `check_anim.py --runtime` | headless run of one scene | `duration=10 seam_end=0.0 seam_last_frame=0.0 determinism=0.0 start_vs_mid=25.85` → loop closes **exactly**, seek is pure, and the picture actually moves |
| `render_anim.py` | `gallery/think-big/index.html` → mp4 | **300 f 1920×1080@30 h264, 754,115 B, 67.5 s wall (225 ms/frame)** — exact frames through `seek(t)`, never a screen recording |
| `frame_diff.py` | source vs code at 0.5/2/4/6/8/9.8 s | mean-abs-diff **0.73, 5.55, 6.72, 2.11, 4.06, 0.73** of 255; the pair sheets show THINK/BIG/sun/START SMALL matching composition and colour (right-hand type marginally heavier) |

**Windows pitfall (found today):** `frame_diff.py` writes the six `pair_*.png` files and prints the scores, then dies composing
`sheet.png`: `Pattern type 'glob' was selected but globbing is not supported by this libavformat build` — the ffmpeg 9.0.2
gyan build on this box has **no glob support**, so the `-pattern_type glob -i dir\pair_*.png` step cannot work.
Workaround verified: copy to a numbered sequence and tile with `-i seq_%03d.png -vf "tile=2xN"` → 184,511 B sheet, inspected.

It installs as a Hermes skill (`~/.hermes/skills/motion2code`), ships 6 rebuilt gallery clips + `compare.html`, and its
`SKILL.md` encodes the contract (one GSAP timeline = one clock; loop is closed in code; every moment checked side by side).

### `givemotion/givemotion` — 83★ MIT (formerly *motionwright*), npm **0.1.6** (7 versions) — **the fast HTML→MP4 renderer**

Zero npm dependencies (one package), Chrome + ffmpeg only, and on Windows it uses `beginFrame` instead of screenshots.

```
doctor   node v24.18.0 · chrome-headless-shell 154.0.8037.57 · ffmpeg 9.0.2
         encoders libx264 libx265 h264_nvenc libvpx_vp9 prores_ks · encoder software (--hardware = NVENC)
render   gm-demo/index.html -> out.mp4   (1920x1080 30fps 10s = 300 frames)
         10 workers, beginframe, "no motion blur: the page uses requestAnimationFrame"
         100% 300/300 @ 134 fps capture  →  done in 4.5 s (67.1 fps)  →  3,721,077 B h264 1920x1080
check    0 errors, 0 warnings, 1 style note:
         [fast-no-blur] 3.52-3.78s, 7.22-7.48s  main > section.scene:nth-of-type(3)
         "Moves 208 px per frame (at 1080p) with no motion blur: it strobes." + ASCII motion strip
```

**4.5 s vs motion2code's 67.5 s for the same 300 frames = ~15× faster**, and the rendered frame is a clean, sharp
title card (inspected). Command surface beyond render: `analyze <video>` (cuts, transitions, camera, pacing, colours,
beat sync, `--compare ref.mp4`), `review` (review pack + beats.png), `snapshot --trail`, `inspect`, `captions`, `words`,
`audio`, `blocks`/`add` (22 editable HTML blocks), `bundle`, `bench`; render flags `--quality --fps --scale 2 (4K)
--frames --redo --transparent (ProRes 4444 / WebM alpha) --motion-blur auto --codec h264|h265|av1 --hardware --workers
--data --json`. MIT, no account, no fee.

**Why this pair matters:** givemotion renders designed code video fast; motion2code reverse-engineers a reference and
proves the match. Today they are the only two tools in the ledger with **both** halves of that loop measurable on Windows.

### Delivery gate re-check (yesterday's action item, closed)

`kino crop -w 608 --height 1080` → `kino resize -w 1080 --height 1920` turned the 1080p card into a real 1080×1920
(0.52 MB → 1.07 MB, no letterbox), then `kino release-checkpoint --min-score 40` **failed honestly at 17.5**:
`no audio stream detected (audio required)`, brightness 37.8 (dark), contrast std 6.5 (flat), saturation 3.6%, cyan cast
20.8%. Correct behaviour — a dark blue gradient brand card and a silent render are exactly what a delivery gate should
reject; `require_audio=false` or a lighter profile is the knob, not a lower bar.
