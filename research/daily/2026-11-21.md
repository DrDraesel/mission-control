## 1. Verified on this machine — `KyaniteLabs/kinocut` 2.0.1 (273★, Apache-2.0)

**What it is:** a local, *guardrailed* video-editing engine with three interfaces over one core — **178 CLI commands** (`kino`), **206 MCP tools**, and a Python `Client`. Formerly `mcp-video`, renamed 2026-07-10. Created 2026-03-21, 1,811 commits, pushed 11-19, **CV: `v2.0.1` published 11-10 on PyPI, npm and the MCP Registry**. It is not a generator: it edits real media, and every edit is validated **before** FFmpeg runs, writes a new file unless `--overwrite`, and returns a structured result plus a *Video Receipt*.

**Why it matters:** the ledger has renderers (fa-render, kinetograph, OpenEdit, raea, Drift) and generators, but nothing that behaves like a **reviewing editor** — it runs quality gates on black frames, silence, loudness and visual metrics, and refuses the cut. It also ships a **first-party Hermes plugin** (`hermes plugins install kinocut`), OTIO import/export, HyperFrames and Revideo renderers, `shorts-render`/`shorts-package`, and a resumable workflow engine.

Measured here (`uvx --from kinocut==2.0.1`, warm cache):

| Step | Measured | Evidence |
|---|---|---|
| install + version | **35 packages in 1.27 s**, `Kinocut 2.0.1`, exit 0 | py3.13.14 |
| `kino doctor` | exit 0 — `workspace`, `runtime_policy`, `sphere_director` OK; optional `image`/`audio`/`crush_shaders`/`object_matte` reported Missing with the exact extra to install | no hard blocker on this box |
| `kino info` | 1920×1080 25 fps h264+aac, 16.96 s | table output |

### The quality gate is real — it rejected every clip for a different, correct reason

| Source | Score @ min 80 | Its finding | Was it right? |
|---|---:|---|---|
| avatar card, `resize -a 9:16` | **47.1** | "quite dark (brightness 28.0), low contrast (12.2), desaturated (0.8%)" | **Yes** — resize **letterboxed**, so 40% of the frame was black bars. Thumbnail confirmed visually. |
| same card, cropped | **36.9** | low contrast (7.4), desaturated (1.5%), **audio clipping (−0.9 dBTP)** | **Yes** — a near-black brand card plus the un-normalised audio. |
| real gym footage | **66.6** | desaturated (2.1%), **audio too quiet (−24.8 LUFS)** | **Yes** — grey gym, camera mic. |
| same, after `normalize-audio -14` | **69.4** | desaturation only — *the loudness complaint disappeared* | **Yes** — closing the loop moved the score and cleared the item. |

Exit code 2 on failure, a JSON envelope with `type: quality_error`, `code: quality_gate_failed`, human-readable defects and the exact retry call shape. **The default 80 bar is a broadcast bar, not a "does it render" bar** — plan to fix (saturate/grade/loudness) or run at a documented lower `min-score` for drafts.

### Pitfalls (write these into any pipeline)
- **`kino resize -a 9:16` PADS, it does not crop.** For a genuine vertical reframe: `kino crop -w <h*9/16> --height <h>` then `kino resize -w 1080 --height 1920`. A padded vertical silently poisons every visual metric downstream.
- **`kino crop` needs explicit pixel width/height** (no aspect preset) and fails if the crop is larger than the source (a 480×860 phone clip cannot yield a 608-wide crop).
- **`kino otio-export` takes `timeline_json`, not a video** ("invalid_json_artifact" if handed media). OTIO *import* is the same shape.
- Captions use **local stock speech (eSpeak NG)** for its own TTS — it is not a neural voice. For branded VO, pair it with edge-tts / ai-voiceover-studio and burn the SRT.

**Installed for use:** shims at `~/.local/bin/kino` + `kino.cmd` (pin 2.0.1 via uvx; **warm invocation 0.54 s**).

## 2. Verified on this machine — `nadermx/backgroundremover` v0.4.5 (8,192★, MIT)

A **seven-year-old, 8.2k★ MIT CLI the ledger never had** — `pip install backgroundremover`, `backgroundremover -i in.jpg -o out.png` (and `-iv/-ov` for video, `-tv` transparent video, `--model u2net|u2netp|…`). Found by `topic:video-editing`, not by any of the 34 phrase probes.

Measured here (`uv run --with backgroundremover`, py3.13):

- **50 packages in 7.74 s**; u2net checkpoint auto-downloaded to `~/.u2net/u2net.pth` — **176,290,937 B**; whole cold run **4 min 12 s**, dominated by that download.
- Output is a genuine **RGBA PNG**: `mode RGBA`, alpha extrema **(0, 255)**, corners exactly `(0,0,0,0)`, centre pixel `(33,37,38,254)`.
- **Caveat 1:** it prints `Device: CPU (no GPU detected – install CUDA toolkit)` on a box with an RTX 5070 Ti → onnxruntime-CPU per-frame inference, so **video** jobs are slow. Use it for stills/thumbnails, or install onnxruntime-gpu.
- **Caveat 2:** u2net segments the *salient object*. On a graphic card it returned the card rectangle (correctly transparent bars, card kept), not the man in it. For person cutouts reach for BiRefNet (MIT, ledgered 11-16) or `kinocut[object-matte]`.

## 8. Integration plan

1. **Adopt `kino` as the pipeline's QC/reframe layer** (not its renderer — keep fa-render/kinetograph/raea for speed). Concretely: `kino release-checkpoint` as a pre-delivery gate on every RunTrack/Bertec/NeuroSync render, and `kino crop`+`resize` for 9:16 social cuts — replacing hand-written ffmpeg crop expressions that fail silently. Apache-2.0 = clean for client work. Optional: `hermes plugins install kinocut` to expose the 206 MCP tools to my own sessions.
2. **Stop trusting `resize -a 9:16` anywhere in the stack** (including in Concat/OpenEdit wrappers): assert the output has no letterbox before it reaches a metric.
3. **Add `backgroundremover`** as the stills/thumbnail cutout step when BiRefNet isn't warranted — with `onnxruntime-gpu` so it stops falling back to CPU.
