## 1. Verified on this machine

### `maskin25/captions.js` — animated word-level captions with **no headless browser** ✅
The one genuinely new pipeline component of the day, and it works.

- npm **`captions.js` 1.10.0** (MIT, 39 versions) + **`@captionsjs/server` 0.1.1**; GitHub 5★, created 2025-10-06.
- One `renderFrame()` draws the caption on a Konva scene. In the browser it overlays a `<video>`; in Node the *same* scene runs on **skia-canvas** and pipes frames straight into FFmpeg. Preview == export, and **no Chromium** in the production path (contrast: OpenEdit / HyperFrames / Remotion all screenshot a browser).
- **On-box evidence:**
  - `npx -y @captionsjs/server@0.1.1 --help` → exit 0, full usage (`burn <video> <words.json>`, `-p/--preset`, `--fps`, `--fonts-dir`, `--crf`).
  - `npx … presets` → **26 presets**: Karaoke, Focus Box, Banger, Acid, Lovly, Marvel, Marker, Neon Pulse, Beasty, Crazy, Safari, Popline, Desert, Hook, Sky, Flamingo, Deep Diver B&W, New, Catchy, From, Classic, Classic Big, Old Money, Cinema, Midnight Serif, Aurora Ink.
  - Real burn: 2.0 s 640×360 test clip + 4-word JSON → **`burn … --preset Karaoke` exit 0, 60 frames h264 in 0.8 s**. Frame at t=1.2 s inspected: `HELLO WORLD` white, **`CAPTIONS` cyan (active word)**, `TEST` white — karaoke highlighting confirmed, not just "a file came out".
- Input formats: `[{word,start,end}]`, Whisper `verbose_json`, or a Deepgram response. Needs `ffmpeg`/`ffprobe` on PATH (or `FFMPEG_PATH`/`FFPROBE_PATH`).
- **Pipeline role:** the missing cheap caption step between Whisper and delivery. `whisper → words.json → captions.js burn → out.mp4`, no browser install, no Remotion licence question, works on 9:16/1:1/16:9 alike.

*(Queued test not done today: the OpenShot 4.1 `--cli` Windows install. The 4.1 blog claim is re-confirmed — "command-line automation … build entire videos" — but the 232 MB installer test stays queued.)*
