## 1. Verified on this machine — `takumi-pdf` turns HTML into a clinical PDF in 66 ms, no browser

`takumi-pdf` **0.20.0** (MIT OR Apache-2.0), 2 packages in 2 s, WebAssembly PDF writer on Node.

**On-box evidence** (a RunTrack-style report: header, 3 metric cards, 4-column table, interpretation, signature line):
- `render(htmlString, {size:"a4"})` → `%PDF-1.7`, **16,335 bytes in 66 ms** (first run), **15,676 bytes in 62 ms** on the fixed layout.
- `pdftotext -layout` recovers the text **with the table columns intact** — vector PDF, selectable text, no rasterisation.
- **Pitfall found:** the first attempt used `flex: 1` cards and the layout collapsed (FORM SCORE jumped up beside the patient line, Right/Asymmetry columns drifted). Rewritten with `display:inline-block; width:31%` + `<colgroup>` widths, it laid out correctly. **`flex: <number>` shorthand is not honoured by takumi's layout engine — use explicit widths and inline-block for cards, colgroup for tables.**
- API is the same shape as `takumi-js`: `DocumentInput = Node | ReactNode | ReactElementLike | string`, so pass an HTML string and skip JSX entirely.

**Why it matters:** the clinical/print reports in RunTrack and Bertec are currently Chromium-printed. This is the same job at 62 ms with **no browser, no Playwright, no EPDF export step**, and `render()` returns a `Uint8Array` you can stream straight to disk or HTTP.

## 2. Verified on this machine — Depth-Anything-V2 is a 0.5 s/frame depth step, and it composites

`DepthAnything/Depth-Anything-V2` — **9,147★, Apache-2.0**, V2-Small 24.8M / Base 97.5M / Large 335.3M.

- Installed via `transformers` (`depth-anything/Depth-Anything-V2-Small-hf`, 1.42M HF downloads) on **CPU** inside uv — no CUDA wheel, no repo clone.
- **Measured:** model load 30.5 s (cold, includes download); **0.50 / 0.50 / 0.61 s per 1920×1080 frame**, output L-mode depth at full 1920×1080.
- **Parallax proof:** thresholded the top 25% depth as subject, softened the mask, shifted the background ±14 px while pushing in on the subject — **48 frames at 960×540 in 2.45 s wall (51 ms/frame including PNG writes)**, ffmpeg H.264 86.6 KB, mid-frame inspected: runner sharp, gym background cleanly shifted. A soft seam is visible at the shorts/background boundary — for production use `BiRefNet_HR-matting` (MIT) or `pymatting` on the depth mask instead of a quantile threshold.
- Output files: `2026-11-12-depth-run_frame.png`, `2026-11-12-depth-parallax.mp4`, `2026-11-12-parallax-frame.png`.

**Why it matters:** depth is the missing step for faceless content — 2.5D parallax on stills, depth-aware text placement, fake rack focus, relighting. At 2 fps CPU (much faster on GPU) a 10 s 30 fps clip is ~2.5 min of CPU work.

## 6. Local video-gen · 16 GB fit

- **PAN 2 is the interesting new route** — Apache-2.0, no territory clause, 20 s clips, and a Windows port that explicitly avoids flash-attn/triton. But be precise about the fit: **weights 33.7 GB fp8 streamed from 34 GB of RAM** (this box: 64 GB ✓), activations are the binding constraint at full 704×1248×241 — start at 448×256×13 frames and scale. It is a *slow, low-res* route on 16 GB, not a 720p production route; the 4090 datapoint (129 s for 13 frames at 448×256) suggests ~10–20× that for a full 20 s clip.

## 7. 3D & web design

- **UltraTex** is the first 2K **texturing** step that fits a 16 GB card: one reference image → PBR texture on an untextured mesh, with a Windows one-click installer that pins tested node versions and verifies the Triton kernel. Combined with Hunyuan3D-2.1 *shape* (10 GB), the chain "image → mesh (10 GB) → texture (6–16 GB)" is now local — the texture stage needs ComfyUI ≥ 0.45.
- **Hunyuan3D-2.1 licence nuance worth recording:** the Territory excludes the **EU, UK and South Korea only**. Unlike MiniMax H3 (which excludes the USA), a US-based lab can use it, subject to the 1M-MAU threshold and AUP.
- **`abi/screenshot-to-code`** closes the inverse direction: design/screenshot → code. Free code, paid model keys; video-to-code needs Gemini. Useful as a *benchmark* for our own HTML→asset pipeline rather than as a dependency.
- **`agent-vision-toolkit`** (MIT) is the small useful piece: `glance` (image Q&A), `ground`/`detect`/`crop` (UI element grounding), long-screenshot OCR, `trace` — pointed at a local OpenAI-compatible endpoint it gives a text-only agent eyes for UI/QA work.
