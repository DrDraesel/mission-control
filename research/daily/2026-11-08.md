## 1. Verified on this machine

### `SubtitleEdit` **5.4.0** ships **`seconv.exe`** — a headless 406-format subtitle converter + burn-in + offline LLM translator ✅

**14,910★ MIT** (`SubtitleEdit/subtitleedit`, pushed today, v5.4.0 released 11-06) — a 14.9k★ ledger gap that had never been verified after 7 weeks of sweeps, and it is the single biggest missing piece of the caption/subtitle stage.

The GUI (111.1 MB portable zip / 58.8 MB Setup.exe) is the famous part. The product is the release asset nobody reads: **`SeConv-Windows-x64.zip` 41.0 MB** — `seconv.exe` + `libse.xml` + SkiaSharp/HarfBuzz, no installer, no Python, no browser.

**On-box evidence (all real, this box):**
- `seconv.exe --help` → exit 0. Usage `seconv [pattern] [format] [options]`, and it **rejects unrecognised options instead of silently no-opping**.
- `seconv.exe formats` → **406 formats** in a box table (SubRip, ASS/SSA, WebVTT, TTML/DFXP, EBU STL, D-Cinema SMPTE 2014 MXF, Avid, Premiere markers, CSV variants, AWS Transcribe JSON, Bilibili `.bcc`…).
- `seconv test.srt advancedsubstationalpha --overwrite` → **ASS written in 32 ms**, valid `[V4+ Styles]` + `PlayResX/Y` header matched to the source video.
- `seconv test.srt advancedsubstationalpha --burn-in-video:probe.mp4 --burn-in-effects:fade:200,font-size-bounce-in` → **burned-in MP4 in 221 ms**, 640×360@30, 60 frames. Frame at t=1.0 s inspected: subtitle **visible and correctly placed** → *"Hola mundo desde SeConv"*.
- `seconv en.srt subrip --translate-to:es --translate-engine:ollama --translate-model:qwen3.8:latest` → **translated 2/2 cues in 58.1 s**, correct register: *"Good morning, the lab opens at eight."* → *"Buenos días, el laboratorio abre a las ocho."*; *"Please step onto the force plate."* → *"Por favor, suba a la plataforma de fuerza."*

Key flags: `--burn-in-video` (+ `--burn-in-ffmpeg-args`, default libx264 CRF 23 / audio copy), `--burn-in-effects` (`fade[:ms]`, `font-kerning`, `font-size-change`, `scroll-up/down`, `rotate-in`, `tilt-bounce`, `font-size-bounce-in`, `fix-rtl`), `--assa-style-file`, `--offset:hh:mm:ss:ms`, `--change-speed`, `--adjust-duration`, `--renumber`, `--fps/--resolution`, `--forced-only`, `--ebu-header-file`, `--dcinema-font`. Translation engines: **auto-started local llama.cpp server** *or* a running **Ollama**. Also OCRs Blu-ray `.sup` (llama.cpp or Tesseract), extracts MKV subtitle tracks, renders via **custom text-format templates**.

**Pipeline role:** one 41 MB binary replaces the whole ad-hoc SRT/ASS path — `whisper → srt → seconv assa --burn-in-effects → mp4`, and gives Spanish/English subtitle pairs with a *local* model instead of a paid translation API. No Chromium, no Node, no Python dependency.

**Installed here:** `~/.local/bin/seconv` (bash shim, verified end-to-end) and `seconv.cmd`, both → `~/.local/bin/seconv-bin/` (exe + `libse.xml` + SkiaSharp/HarfBuzz DLLs). `seconv formats` works from a plain cmd prompt targeting that exe.

### `Gyroflow` **1.7.0** — headless video stabilization ✅

**9,694★ GPL-3.0** (`gyroflow/gyroflow`, v1.7.0 released **11-07**, never ledgered). `Gyroflow-windows64.zip` 79.7 MB.
- `Gyroflow.exe --version` → exit 0, **`Gyroflow v1.7.0`**, Qt 6.7.3, bundled ffmpeg (`avcodec-63.dll`), x86_64, MDK 0.40.1.
- Documented **CLI mode**: when any argument other than `--open` is passed it runs headless — `Gyroflow.exe clip.mp4 --preset x.gyroflow --out-params '{"codec":"H.265/HEVC","use_gpu":true,"output_folder":"./renders"}' --stdout-progress --overwrite`, plus `-j N` parallel renders, `--watch <folder>` auto-processing, `--export-project`, `--export-stmap`.
- Not rendered here: stabilization needs IMU data (or a `.gyroflow` project built in the GUI), and there is no gyro clip on this box. Binary launch + CLI surface verified; the render path is documented, not measured.

**Pipeline role:** the camera-footage cleanup step for RunTrack/Bertec vision — stabilize before pose estimation, batch with `--watch`.

## 7. Integration plan

1. **Make `seconv` the subtitle stage.** `whisper → .srt → seconv … assa --burn-in-effects:fade:200 → .mp4`. One 41 MB binary replaces the `drawtext`/ASS glue, and `--offset`/`--change-speed`/`--renumber` handle the fix-ups that currently need custom Python. `captions.js` stays the choice when word-level karaoke is the look.
2. **Use `seconv --translate-to` + Ollama for bilingual cuts.** Verified EN→ES; the prompt can be overridden (`--translate-prompt`) — add a clinical glossary so "force plate"/"baseline" stay consistent.
3. **Stabilize camera footage before pose work.** `Gyroflow.exe clip.mp4 --preset runtrack.gyroflow --stdout-progress --overwrite` (or `--watch` a capture folder) for RunTrack/Bertec; fall back to `vidstab` when the clip has no IMU.
4. **Install `threejs-skills`** before the next 3D-web artifact — it is the cheapest fix for agent-written three.js API drift.
5. **ComfyUI update stays the standing #1 action** (19 versions behind, 25th run).
6. **Trial cinecode** against the existing HyperFrames/captions.js path on one 30 s vertical — same brief, compare time-to-MP4 and whether the frames pass the medical-content bar.
