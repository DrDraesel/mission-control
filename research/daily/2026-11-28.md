### `academa-labs/manimgx` 0.1.1, 2,928★ MIT — the Manim API on a Rust GPU core, MEASURED

Ledgered **2026-10-11** (via `fresh-agents`, `manim-ecology`) and reported OLD every run since — the fourth
confirmed instance of the *ledgered ≠ evaluated* trap (after open-edit, kinocut, lottie-converter).

- Install: PyPI `manimgx` (2 releases, `cp313-abi3` wheels incl. **`win_amd64`**, requires **Python ≥3.13**).
  `uvx --from manimgx manimgx --help` → **22 pkgs / 860 ms**, exit 0.
- Four commands: `render`, `inspect`, `preview`, `present`. `render` flags: `-o`, `-r WxH`, `--fps`,
  `--preset`, `--crf` — **no alpha/transparent flag**.
- **531 exported names**, i.e. a near-complete Manim CE surface: `Scene`, `ThreeDScene`, `ZoomedScene`,
  `MovingCameraScene`, `Surface`, `ThreeDAxes`, `MathTex`, `Axes`, `BarChart`, `Brace*`, `Code`,
  `ComplexPlane`, `AnimationGroup`, up-to-date animation names (`AddTextWordByWord`, `Circumscribe`…).
- **Measured renders (this box, RTX 5070 Ti):**

| scene | size | wall | stored frames |
|---|---|---|---|
| title card (Write/Create/Transform, 4.20 s) | 1280×720 @30 | **0.6 s** | 107 |
| same scene | **1920×1080 @60** | **0.6 s** | 212 (nominal 253) |
| 3D `Surface` + `ThreeDAxes` + ambient camera rotation (2.50 s) | 960×540 @30 | **4.9 s** | 76 |
| `MathTex(r"e^{i\pi}+1=0")` + caption (2.00 s) | 1280×720 @30 | **0.3 s** | — |

- Frames inspected with vision: the title card is clean Computer-Modern-style type with correct kerning,
  anti-aliasing and a blue rule; the 3D saddle surface renders with checkerboard shading, proper depth and
  arrow-tipped axes; **the Euler identity typesets with no LaTeX install** (italic *e*, superscript *iπ*).
- **`inspect` is a real gate:** it wrote `TitleCard.storyboard.png`, listed 7 plays with time ranges and
  `title_card.py:11` source lines, then named three genuine defects
  (`kicker and box: Square runs through the text`, same for `title`, `dot has its edge through the text`) —
  and **`inspect` exited 1**. `render` prints the same defect list after writing the MP4.
- **PITFALL — the output is not CFR.** The engine dedupes static holds into single frames (a 4.2 s scene at
  "60 fps" stores 212 frames, `avg_frame_rate` 50.3). Timing is preserved in PTS, so players are fine, but a
  frame-indexed tool or an NLE that assumes constant rate will drift: re-encode `-fps_mode cfr -r 60`
  before handing it downstream. (This ffmpeg 9 build has **no `-vsync`** — that flag was removed.)
- Licensing: repo **MIT**; PyPI metadata carries no licence field. Engine is `wgpu` (Vulkan/D3D12/Metal), with
  Mesa lavapipe as a CPU fallback on Linux; audio import decodes through bundled LGPL FFmpeg.
- When to use: math/data/3D explainers, kinetic-typography cards, and any scene where Manim's ecosystem is the
  right vocabulary but its render time is not. When not to: transparent overlays (no alpha), and anything
  needing a GUI timeline.

### `smacke/ffsubsync` 0.5.1, 7,969★ MIT — subtitle↔audio alignment, MEASURED

Found by the `topic:captions` debut; 5 years old, never ledgered (no query ever named subtitle *sync*).
Built here: a 8.69 s edge-tts speech clip muxed to black video, plus a hand-made SRT shifted **+1.5 s**.

- `uvx --from ffsubsync ffsubsync speech.mp4 -i shifted.srt -o synced.srt` → **0.79 s**, 18 pkgs on first run.
- Output: `score: 416.000`, **`offset seconds: -1.790`**, `framerate scale factor: 0.960`; it dropped the first
  cue (`start < 0`) and rewrote the other two into `synced.srt`.
- Read it as: the tool works on Windows with only ffmpeg, and it estimates **both** an offset and a rate scale.
  The rate estimate is the risk — on hand-authored cues it may "correct" a drift that is really your cue
  placement, so diff the output (or use a tool that only shifts) before burning subtitles in.
- Pipeline role: the step **before** `seconv assa --burn-in` — a translated or vendor-supplied SRT that is a
  second or two off is the most common reason a burned video looks amateur.

### `amietn/vcsi` 7.0.17, 644★ MIT — video contact sheets, MEASURED

Also new in today's sweep (via `topic:thumbnail`, of all places). A 21.08 s clip → `vcsi loop20.mp4 -o sheet.jpg -g 4x3 -w 1600`
→ **12-sample 4×3 contact sheet, 1600 px, 93,085 B in 1.8 s** (uvx overhead included). Pure Python
(pillow+numpy+ffmpeg). Use it as the cheap storyboard/QC artifact for every render, and as the review sheet
for delivered cuts — it is the same job `kino release-checkpoint` does, minus the scoring.

### `HKUDS/CLI-Anything` 67,279★ Apache-2.0 — a 67k★ ledger gap, and its registry measured

Never ledgered because no query names *agent-native CLI*. It generates/marshals **CLI harnesses that make
GUI+CLI software agent-drivable**, with preview / live-preview / trajectory loops.

- `uvx --from cli-anything-hub cli-hub --help` → PyPI `cli-anything-hub` **0.4.1** (MIT, ≥py3.10, 8 releases),
  **7 pkgs / 1.7 s**, exit 0. Commands: `can`, `info`, `install`, `launch`, `list`, `matrix`, `previews`,
  `search`, `uninstall`, `update`.
- `cli-hub list` → **103 CLIs (79 harness + 24 public)** across 35 categories.
  `cli-hub search video` → **`kdenlive`** (video editing/render **via melt**), **`shotcut`** (melt/ffmpeg),
  `openscreen`, `videocaptioner`, `palmier`, plus paid-API generators (Veo/Jimeng/Vivideo).
  `cli-hub info blender` → harness `cli-anything-blender` (**needs blender ≥4.2**);
  `info kdenlive` → **needs `melt`**.
- **The caveat that decides it: a harness is a wrapper, not an engine.** There is **no Blender and no melt on
  this box**, so nothing here is runnable today — but the day a real NLE lands, `cli-hub install kdenlive`
  is the shortest path from "GUI app" to "agent tool". Note the hub's own `blender` harness is the generic
  3D-link the pipeline has always lacked.
